# Contributing

This repository is a starter. In the public starter, keep every example generic. In your own copy, record only what you have agreed to say.

## Before you add a note

- Read [SECURITY.md](SECURITY.md).
- Copy [_templates/topic-template.md](_templates/topic-template.md).
- Put the file in the folder that matches the topic. One topic per file.
- Name the file with lowercase words and hyphens, such as `how-a-request-moves.md`.
- Set `status` to `draft` until the owner has read the exact text and said it is right.

## Changing a note that is already confirmed

Prefer a pull request: a suggested change the owner can accept or reject. In the pull request, name the file, say what changed, and say why. Keep unrelated topics in separate pull requests.

If you are editing the file directly, add a dated line under **Change log**, set `status` back to `draft`, and ask the owner to confirm. After they agree, set `status` to `confirmed` and set `last_reviewed` to that day.

## Examples

Files whose names start with `example-` show the pattern. They are not real decisions. Do not cite them. Delete them from your own copy when you no longer need the pattern.

## Reports from assistants

An assistant that discovers a new fact may add it only as a `draft`, with a real source link or a dated conversation. The owner confirms it before anyone treats it as settled.

## Tone

Write the way you would explain the rule to a new teammate. Short sentences. One idea per file. Plain words.
