# Replace with a short title

## Summary

Two to four sentences in plain language. Describe one rule, one workflow, or one decision. Say how it applies to you.

## Details

Add the steps, the boundary, or the context a helper would need. Keep it short enough to read in a few minutes.

If this section starts to cover a second decision, stop and make another file. Link that file by its path, for example `operations/how-a-request-moves.md`.

If you include a number you are not sure of, write the word **estimate** next to it. If you do not have the number, leave it out.

## Sources

List the same sources as in the block at the top, one per line, so a person can click them.

- A real web link to the page you actually used, or
- `Conversation with the owner on YYYY-MM-DD` when the source is a decision you made, not a web page

Do not invent a link. Replace `https://example.com/...` before anyone relies on this file.

## Open questions

- Write what is still unknown.
- Delete a question only after the owner has answered it. Do not guess and then delete the question.

## Change log

- YYYY-MM-DD — Created as draft.

## How to fill this in

The block between the `---` lines is front matter. Assistants read it first.

| Field | What to put |
| --- | --- |
| `title` | A short name for this one topic. Match the heading below. |
| `status` | `draft` or `confirmed`. Use `draft` until the owner has agreed to the exact words. Use `confirmed` only after they say it is right. |
| `owner` | A first name or a role. A home address or an email is not needed. |
| `last_reviewed` | The day the owner last agreed the text is right, written year-month-day, such as `2026-04-02`. On a brand-new draft, leave the placeholder or use the day you wrote it, and keep the status `draft`. |
| `sources` | Real links, or a dated conversation. These must match the **Sources** section. |

Delete this "How to fill this in" section from your copy after you have used it once. It is instructions, not part of the topic.
